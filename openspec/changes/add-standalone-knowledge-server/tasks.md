开发阶段（第 1–3 节）在 Windows x64 验证；Linux 专属启动行为可在隔离 Linux 环境验证。CentOS 7 x64 仍由验收人员在实际目标服务器手工验证，不以本地 Linux 或 mock 结果替代。

## 2. Markdown 导入与检索

- [x] 2.1 实现 Markdown 解析、分段及来源定位，按库流式上传。测试覆盖代码围栏、长段落、UTF-8 BOM、CRLF 和来源坐标；验证原文、行号及 SHA-256 不变，非法路径、重复路径及非 UTF-8 文件不发布部分批次。
- [x] 2.2 实现整库版本的独立构建、原子发布、删除退役和进程重启恢复。用真实 Edge 验证中断不发布半成品、重导成功后未上传文档不再可查、并发查询不混代、删除不碰其他库或源文件、删除和同名重建后旧导入无法发布。保留 Edge 配置但移除必要数据段，验证重开后 Web 与 MCP 均明确报存储错误而不是零命中；在 Windows 确认本地提交，CentOS 7 的 tmpfs 行为见 4.1。
- [x] 2.3 实现范围内 BM25、完整技术名称优先和来源证据。用固定合成小样本预先指定必须出现和不得出现的证据，覆盖中英文、嵌套路径、同名文件、重复正文的不同来源、`C++`／`C++17`、`std::vector`、切片边界及普通查询不解释操作符。核对原文和来源，验证范围外高分候选不占预算、只改变范围外词频不改变范围内排序，并区分无已发布索引、正常零命中和存储错误。只断言契约要求的相对顺序，不固定完整 BM25 排名。
- [x] 2.4 接入显式配置的 Embedding、向量代际校验和混合检索。用合成文档和确定性向量，仅 mock 回环 HTTP `/v1/embeddings`，保留真实 HTTP 客户端、Qdrant Edge 和检索逻辑。验证同一查询在纯全文时找不到指定库内证据，打开 Embedding 后能找回，且范围外近邻不占预算。验证旧代际隔离、跨路去重保留不同来源、请求失败或向量无效时保留全文，以及关闭时不发 Embedding 请求。
- [x] 2.5 接入独立可选的 Rerank，仅 mock 回环 HTTP `/v1/rerank`。关闭 Embedding 时，用打乱数组顺序的评分响应验证按 `index` 映射且确实改变同类有限候选的顺序；两者开启时，确认精排收到融合后的候选，即使近似名称评分更高，完整名称仍在前。核对同分保持基础顺序、候选集合、原文、来源及命中类别不变。用 HTTP 失败和非法评分验证保留当次基础排名；Embedding 失败不影响独立配置的全文精排；关闭或无候选时不发 Rerank 请求。文档说明独立配置及当次状态。
- [x] 2.6 实现 CentOS 7 模型自动配置，前台与后台 `start` 复用启动解析。以临时 Claude Code 用户配置及回环 HTTP mock 验证继承 `OMP_OFFLINE=1` 时无模型参数可导入并使用两个目标模型，核对 4096 维、路径前缀和 `/v1` 拼接、Bearer 认证、精排响应省略 `model`、实际混合检索和精排状态。验证未设置 `OMP_OFFLINE=1` 时及运行控制命令时不加载配置，配置不可用时脱敏告警且全文可用，单个模型显式配置优先且不继承网关 Token，另一模型仍可采用自动配置。通过 `--help` 说明启动前提、回退、凭据边界和既有库重导。

## 4. 部署验收

### CentOS 7 运行与发布

使用普通账号管理后台服务：

```sh
./rust-knowledge-server start
./rust-knowledge-server status
./rust-knowledge-server stop
```

`start` 支持 `--listen` 等启动参数（见 `./rust-knowledge-server --help`）。日志位于 `/dev/shm/rust-knowledge-server/daemon.log`。后台进程退出后不会自动重启。

推送 `v<主版本>.<次版本>.<修订号>` 标签会触发 [Release CentOS 7](../../../.github/workflows/release.yml) 工作流，只构建和发布 CentOS 7 x64 压缩包。手动运行该工作流只上传 Actions 产物，不创建 GitHub Release。目标机手动构建见 [CentOS 7 构建脚本](../../../release/build-centos7.sh)。

### 目标环境验收

执行 4.1、4.2 时，服务启动不继承 `OMP_OFFLINE=1`，也不传模型参数。

- [ ] 4.1 在干净的 Windows x64 环境与 CentOS 7 x64 目标服务器直接运行最终发布文件，关闭 Embedding 和 Rerank，以真实浏览器整批导入操作者提供的全部 Markdown 语料，不用抽样替代；源文件只读，整批验收不进日常 CI。导入前选定查询及预期原文、相对路径和行号；导入后和同一数据根进程重启后须找回预期证据，操作记录须保留。Windows 验证固定主目录路径与本地持久化。CentOS 7 由验收人员手工验证 glibc 2.17、运行依赖、单文件离线启动、Edge 写入及重开、范围 IDF、非 root 使用固定 tmpfs、占用或重定向路径被拒且不回退、tmpfs 空间不足时不替换旧版本；再用批准的隔离验收环境验证 shm 清空后空库启动、旧审计不复现，可重新建库并导入。两端记录导入耗时和数据根峰值占用，并确认无附带数据库进程或其他分发文件。
