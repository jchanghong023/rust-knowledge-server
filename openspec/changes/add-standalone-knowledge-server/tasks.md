# Tasks

开发阶段（第 1–3 节）在 Windows x64 验证；Linux 专属后台命令可在隔离 Linux 环境验证生命周期。CentOS 7 x64 仍由验收人员在实际目标服务器按 4.1 手工验证，不以本地 Linux 结果替代。

## 1. 独立进程与数据库生命周期

- [x] 1.1 确定 Windows x64 最低版本，明确 CentOS 7 x64 的 glibc 2.17 构建基线。建立独立 Rust 入口和内嵌 Web 资源构建方式，锁定 Qdrant Edge；先在 Windows 验证单个文件离线启动、Edge 写入及重开、所需的稀疏 IDF 语料过滤和实际运行依赖，再推进其余实现。CentOS 7 对应验证见 4.1。
- [x] 1.2 移除数据根覆盖环境变量及路径解析；Windows 固定使用当前用户的 `~/.rust-knowledge-server` 并保留本地块存储校验，CentOS 7 固定使用 `/dev/shm/rust-knowledge-server`，只允许启动用户独占且托管目录必须在同一 tmpfs 挂载。保留数据根排他锁、每库按需打开和正常停机。Windows 验证无论是否设置旧环境变量都使用同一固定根，根不可用和并发启动明确失败且不回退；CentOS 7 见 4.1。同步 `--help` 和 README 的双平台路径、启动方式和数据保留说明。
- [x] 1.3 实现 CentOS 7 的 `start [启动选项]`、`status` 和 `stop`，复用前台服务和数据根独占；同步 `--help` 和 README。实测脱离终端、HTTP 就绪和实际地址、重复启动及端口占用、正常停机与数据保留、异常退出后陈旧端点恢复；Windows 不提供后台命令。

## 2. Markdown 导入与检索

- [x] 2.1 实现 Markdown 解析、分段及来源定位，按库流式上传。测试覆盖代码围栏、长段落、UTF-8 BOM、CRLF 和来源坐标；验证原文、行号及 SHA-256 不变，非法路径、重复路径及非 UTF-8 文件不发布部分批次。
- [x] 2.2 实现整库版本的独立构建、原子发布、删除退役和进程重启恢复。用真实 Edge 验证中断不发布半成品、重导成功后未上传文档不再可查、并发查询不混代、删除不碰其他库或源文件、删除和同名重建后旧导入无法发布。保留 Edge 配置但移除必要数据段，验证重开后 Web 与 MCP 均明确报存储错误而不是零命中；在 Windows 确认本地提交，CentOS 7 的 tmpfs 行为见 4.1。
- [x] 2.3 实现范围内 BM25、完整技术名称优先和来源证据。用固定合成小样本预先指定必须出现和不得出现的证据，覆盖中英文、嵌套路径、同名文件、重复正文的不同来源、`C++`／`C++17`、`std::vector`、切片边界及普通查询不解释操作符。核对原文和来源，验证范围外高分候选不占预算、只改变范围外词频不改变范围内排序，并区分无已发布索引、正常零命中和存储错误。只断言契约要求的相对顺序，不固定完整 BM25 排名。
- [x] 2.4 接入显式配置的 Embedding、向量代际校验和混合检索。用合成文档和确定性向量，仅 mock 回环 HTTP `/v1/embeddings`，保留真实 HTTP 客户端、Qdrant Edge 和检索逻辑。验证同一查询在纯全文时找不到指定库内证据，打开 Embedding 后能找回，且范围外近邻不占预算。验证旧代际隔离、跨路去重保留不同来源、请求失败或向量无效时保留全文，以及关闭时不发 Embedding 请求。
- [x] 2.5 接入独立可选的 Rerank，仅 mock 回环 HTTP `/v1/rerank`。关闭 Embedding 时，用打乱数组顺序的评分响应验证按 `index` 映射且确实改变同类有限候选的顺序；两者开启时，确认精排收到融合后的候选，即使近似名称评分更高，完整名称仍在前。核对同分保持基础顺序、候选集合、原文、来源及命中类别不变。用 HTTP 失败和非法评分验证保留当次基础排名；Embedding 失败不影响独立配置的全文精排；关闭或无候选时不发 Rerank 请求。文档说明独立配置及当次状态。

## 3. 浏览器与 MCP

- [x] 3.1 实现 8 位 ASCII 工号登记、服务端会话、同源校验与审计；验证前导零保留、错误格式拒绝、无会话或跨源变更被拒、工号不能由请求覆盖，审计不可写时不开始操作。故障注入覆盖业务提交前中断及提交后、追加结果前中断，验证数据根仍在时，进程重启后能准确恢复、无重复结果、不永久停在进行中。
- [x] 3.2 实现浏览器的库列表、创建、Markdown 上传、导入状态、确认后删除、搜索及原文来源展示；用真实浏览器完成导入、提示整库替换后重导、查询和删除，核对工号归属与终态。文档说明登记不认证、所有已登记用户权限相同，以及支持的上传格式。
- [x] 3.3 锁定 Rust MCP SDK，接入同址 `/mcp`、Host／Origin 策略和只读 `knowledge_search`。用非回环 Host 验证原生客户端请求无 Origin 时可发现和调用、非法 Origin 返回 403。验证没有写工具、不需要浏览器会话、四类查询结果语义、同检索与精排条件下等效 Web／MCP 结果一致；复用 HTTP mock 核对单次降级在两个入口如实呈现，不重复检索层的排序和异常矩阵。提供标准 MCP 客户端通过原生 Streamable HTTP 连接 `/mcp` 的具体配置示例。
- [x] 3.4 删除手动配置主机名单的启动参数与帮助说明，改为 Web 和 MCP 根据连接端点校验 Host。验证默认支持非回环 IP 直连，显式绑定回环时仅本机可访问，端点不匹配和跨源请求仍被拒绝。
- [x] 3.5 在 Web 提供无需登记的只读活动记录。显示滚动 30 天内成功登记的去重工号和最近登记时间；可查看每个工号仍保留的知识库操作、开始时间、目标库和结果。验证 30 天边界、前导零、重复及失败登记、无操作人员、旧操作及已删除库仍可查、后台导入正确归属、进程重启、读取错误与空历史可区分；用真实浏览器验证未登记和会话失效时可读且不能执行知识库操作，页面及响应不包含搜索词、原文或凭据，MCP 不提供活动记录。

- [ ] 4.1 在干净的 Windows x64 环境与 CentOS 7 x64 目标服务器直接运行最终发布文件，关闭 Embedding 和 Rerank，以真实浏览器整批导入操作者提供的全部 Markdown 语料，不用抽样替代；源文件只读，整批验收不进日常 CI。导入前选定查询及预期原文、相对路径和行号；导入后和同一数据根进程重启后须找回预期证据，操作记录须保留。Windows 验证固定主目录路径与本地持久化。CentOS 7 由验收人员手工验证 glibc 2.17、运行依赖、单文件离线启动、Edge 写入及重开、范围 IDF、非 root 使用固定 tmpfs、占用或重定向路径被拒且不回退、tmpfs 空间不足时不替换旧版本；再用批准的隔离验收环境验证 shm 清空后空库启动、旧审计不复现，可重新建库并导入。两端记录导入耗时和数据根峰值占用，并确认无附带数据库进程或其他分发文件。
