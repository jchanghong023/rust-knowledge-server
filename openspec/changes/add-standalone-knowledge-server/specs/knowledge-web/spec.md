# Spec Delta

## Purpose

提供统一的浏览器入口，用工号留痕地管理知识库、导入文档和测试搜索；工号用于记录操作者自报身份，不用来验证真实身份或分配权限。

## ADDED Requirements

### Requirement: 浏览器工号登记

浏览器管理和搜索 MUST 要求有效登记会话。服务 MUST 只接受恰好 8 位 ASCII 数字作为工号，按字符串保留前导零；MUST NOT 查名册、要求密码、验证员工身份或按工号划分权限。

#### Scenario: 有效工号登记
- **WHEN** 用户提交 `00001234`
- **THEN** 服务以原字符串建立会话并记录成功登记；该会话能管理和搜索所有知识库，与其他已登记会话权限相同

#### Scenario: 拒绝非精确格式或无会话操作
- **WHEN** 工号位数不等于 8、含非 ASCII 数字或空白，或者调用者未建立有效会话便调用浏览器管理或搜索接口
- **THEN** 服务不创建无效会话、不执行管理或搜索，并提示正确格式或重新登记；不影响独立的只读 MCP 接口

#### Scenario: HTTP 同源检查无需配置浏览器地址
- **WHEN** 浏览器以 HTTP 访问服务端 IP，或用 `localhost` 访问本机，发起登记或 POST/DELETE API 请求
- **THEN** 服务先按连接端点校验 Host，再校验单个 HTTP Origin 的主机和端口与 Host 一致；缺少 Origin、重复头或来源不匹配时拒绝，不读取转发头作为替代

### Requirement: 浏览器管理与搜索测试

已登记用户 MUST 能在浏览器创建和删除知识库、上传 Markdown、监看导入结果，并对已发布内容测试搜索和查看实际证据。创建不得覆盖同名库。变更操作 MUST 经同源校验，删除 MUST 明确确认后才执行；已有发布版本的库重导前 MUST 提示本次上传将整库替换，未上传的旧文档将不再可查。

#### Scenario: 导入后测试搜索
- **WHEN** 用户上传原始 Markdown 到指定知识库并等待导入完成
- **THEN** 页面区分进行中、成功、失败，以及故障后的结果未知（仅在无法确认时）；可搜索已发布结果，查看真实正文、库名、相对路径、行号范围、文档版本、本次实际检索方式及是否采用精排

#### Scenario: 管理删除不修改源文档
- **WHEN** 用户明确确认删除一个知识库
- **THEN** 成功后该库不再出现在新查询中，不修改上传者的原始文件，不影响其他知识库

#### Scenario: 跨源管理请求不执行
- **WHEN** 已登记浏览器被其他站点诱导发出不符合预期来源的变更请求
- **THEN** 服务拒绝请求且不改变知识库状态

### Requirement: 记录工号和操作

服务 MUST 在固定数据根记录成功的工号登记，以及浏览器创建、导入、删除和搜索的操作结果。工号 MUST 来自登记会话；记录 MUST 表明这是自报工号，不是身份验证。日志 MUST NOT 保存搜索词、原文、会话凭据或模型凭据。

#### Scenario: 记录成功或失败的操作
- **WHEN** 已登记的用户发起创建、导入、删除或搜索，操作成功或失败
- **THEN** 可查到时间、自报工号、操作类型、目标库（如有）和结果；后台导入的记录仍归属于提交该任务的会话工号，不被其他用户的新会话覆盖

#### Scenario: 进程重启及记录不可用
- **WHEN** 原数据根仍在且服务进程重新启动，或登记及操作开始时无法写入记录
- **THEN** 进程重启后保留先前记录；无法记录登记或操作的开始时，拒绝登记或开始新的浏览器操作

#### Scenario: CentOS 7 机器重启
- **WHEN** CentOS 7 机器重启导致 tmpfs 的内容丢失
- **THEN** 旧审计记录不可恢复；新启动的服务正常记录新的操作

#### Scenario: 操作提交后未能追加结果记录
- **WHEN** 浏览器操作执行中断，或实际提交后因进程退出、数据根写入失败等原因未能追加结果，且原数据根仍在
- **THEN** 查询操作状态时不得把已提交的变更报告为失败，也不得把仅有开始记录的操作报告为成功；进程重启后可确认的提交须恢复实际结果，可确认未提交的操作标记为中断，无法确认结果的记录标为「结果未知」，不永久显示「进行中」

### Requirement: Web 查看最近登记及个人操作历史

网页 MUST 提供只读的「活动记录」。任何能访问 Web 的访客 MUST 能查看名单和个人历史，包括未登记、已退出或会话失效的访客；不检查会话或角色。这不免除知识库管理、导入状态和 Web 搜索的登记要求。名单 MUST 按服务端查询时刻向前滚动 30 天，以成功登记事件为依据，按工号去重、保留前导零，显示每个工号最近的登记时间（标明时区）并按时间倒序排列。页面 MUST 明示工号由用户自报，不代表已验证身份；名单也不代表当前在线人员。

#### Scenario: 重复登记、时间边界与无操作人员
- **WHEN** 同一工号在窗口内登记多次，另有工号最后一次成功登记恰在 30 天边界、早于该边界，或仅发起过失败的登记
- **THEN** 只列出窗口内成功登记过的工号，包含边界时刻，同一工号只出现一次且使用最近登记时间；没有操作的工号仍列出，其操作历史显示为空

#### Scenario: 按工号查看仍保留的操作历史
- **WHEN** 访客选中名单中的工号，且该工号有 Web 创建、导入、删除或搜索记录
- **THEN** 按操作开始时间倒序显示该工号仍保留的操作，不用 30 天窗口裁剪操作历史；每个操作显示一次，包含开始时间（标明时区）、操作类型、目标库（如有）及实际结果或当前状态。已删除库的历史仍可查看；不展示搜索词、原文、凭据或未经归属的 MCP 调用

#### Scenario: 无需登记即可查看，原有操作权限不变
- **WHEN** 未登记、已退出或会话失效的访客打开活动记录，或尝试管理知识库、查询导入状态或执行 Web 搜索
- **THEN** 访客可查看名单及个人历史，但未持有效登记会话的知识库操作仍按原规则拒绝；MCP 不提供活动记录入口

#### Scenario: 记录不可读取
- **WHEN** 查看名单或个人历史所需的记录无法读取
- **THEN** 返回明确的读取错误，不显示为成功读取但没有记录

#### Scenario: 记录随数据根保留或清空
- **WHEN** 服务进程重启且数据根仍在，或 CentOS 7 机器重启致 tmpfs 清空
- **THEN** 前者仍可按上述窗口和工号查看已记录的活动；后者只显示新数据根中的新活动，不恢复旧记录
