# Spec Delta

## Purpose

规定独立知识库服务的交付与数据生命周期：通过 Markdown 上传建立共享知识库，并让浏览器和 MCP 查询同一批已发布的原始证据。

## ADDED Requirements

### Requirement: Windows 和 CentOS 7 单文件运行

服务 MUST 分别为 Windows x64 与 CentOS 7 x64 交付一个可执行文件，内含 Web 资源和进程内数据库能力；不承诺其他平台。服务 MUST 独立运行，MUST NOT 依赖任何客户端运行时、独立 Qdrant 进程、附带数据库程序、容器、外部前端文件或启动时联网下载。

#### Scenario: 干净环境离线启动
- **WHEN** 用户在受支持的 Windows x64 或 CentOS 7 x64 环境取得对应可执行文件，且该平台的固定数据目录可用
- **THEN** 该文件独立启动 HTTP 服务，提供浏览器与 MCP 入口，无需另行安装或启动数据库，也不对外监听数据库接口
- **AND** 进程退出或更换可执行文件不改变索引和操作记录；数据目录仍在时，重新启动可继续使用

### Requirement: 无须独立配置文件启动

监听地址、MCP Origin 和检索融合模式 MUST 只通过命令行设置。Embedding 和 Rerank 可通过命令行独立配置；唯一的配置文件例外是 CentOS 7 在 `OMP_OFFLINE=1` 时只读复用现有 Claude Code 用户配置来提供模型默认值。服务 MUST NOT 引入独立配置文件、读取数据根覆盖环境变量或提供数据路径及手动配置允许主机的参数。

#### Scenario: 直接查看帮助与拒绝无效参数
- **WHEN** 用户运行 `--help`，或传入未知、不完整或无效的启动参数
- **THEN** 帮助成功退出并列出启用项、默认值、参数依赖、各平台固定数据根、数据保留规则及 Web/MCP 使用方式；无效参数明确失败，不监听端口、不初始化数据目录、不回显密钥

#### Scenario: CentOS 7 零额外配置启动模型
- **WHEN** CentOS 7 x64 的启动进程已继承 `OMP_OFFLINE=1`，启动账号已有有效 Claude Code 网关配置，且未显式配置模型
- **THEN** 前台直接运行和后台 `start` 均无需模型参数、新配置文件或另填密钥；只在启动时读取 `$CLAUDE_CONFIG_DIR/settings.json`（该变量未设置或为空时使用启动账号的 `~/.claude/settings.json`）中的 `env.ANTHROPIC_BASE_URL` 和 `env.ANTHROPIC_AUTH_TOKEN`，变更配置须重启
- **AND** 保留网关路径前缀，以该 HTTP(S) 基址调用 `/v1/embeddings` 的 `Qwen3-Embedding-8B`（4096 维）和 `/v1/rerank` 的 `Qwen3-Reranker-8B`，使用该 Token 的 Bearer 认证；不在启动时探测网关，不猜测其他地址、不回退公网，不把 Token 加入启动参数、写入服务数据或打印到日志
- **AND** 已有纯全文索引仍可查询；从原始 Markdown 重导生成完整兼容向量后方可获得语义召回，不自动重导

#### Scenario: 显式模型配置独立优先
- **WHEN** CentOS 7 的启动进程已继承 `OMP_OFFLINE=1`，且显式提供任一模型的命令行参数
- **THEN** 对该模型仍按命令行要求独立校验和配置，不以网关配置补齐部分参数，也不继承其中的 Token；未显式配置的另一模型仍可采用自动配置

#### Scenario: 不自动配置模型
- **WHEN** 使用 Windows、CentOS 7 启动进程未继承 `OMP_OFFLINE=1`，或运行帮助、`status`、`stop`
- **THEN** 不为模型自动启用读取 Claude Code 配置；服务启动时未显式配置的模型保持关闭

#### Scenario: 网关配置不可用
- **WHEN** CentOS 7 的启动进程已继承 `OMP_OFFLINE=1`，有模型需要自动配置，但所需配置缺失、无法读取或无效
- **THEN** 跳过需要该默认配置的模型并给出脱敏启动告警，不阻止全文服务启动或影响独立的显式模型配置

### Requirement: CentOS 7 后台服务管理

CentOS 7 的单文件 MUST 支持普通用户运行 `start [启动选项]`、`status`、`stop`，且直接运行仍在前台。后台进程 MUST 脱离启动终端，并复用相同 HTTP 服务、数据根排他锁和正常停机流程。控制端点与后台日志 MUST 位于固定数据根，控制 MUST 仅限启动用户且不经 TCP 开放；不得按残留 PID 向进程发送信号。Windows 不提供后台管理命令。服务不负责异常退出后拉起或开机自启。

#### Scenario: 启动成功或失败
- **WHEN** 用户以 `start` 启动，或因数据根已被占用、HTTP 端口已被占用等原因无法启动
- **THEN** 正常情况只在 HTTP 和控制端点就绪后返回成功；失败时返回非零和诊断，不打断已有实例，也不遗留本次后台进程

#### Scenario: 查看状态与正常停机
- **WHEN** 用户查看状态，或要求停止一份运行中的后台实例
- **THEN** 运行状态报告实际 PID 和 HTTP 监听地址；`stop` 在 HTTP 停止且在途操作收尾后返回成功，不清除已发布数据和审计

#### Scenario: 未运行或异常退出
- **WHEN** 后台实例不存在或异常退出后仅剩控制端点残留
- **THEN** `status` 明确报告未运行并返回非零；`stop` 不向其他进程发请求并报告未运行；下一次 `start` 可正常启动

### Requirement: 统一的知识库文件根

CentOS 7 的服务数据根 MUST 固定为 `/dev/shm/rust-knowledge-server`（tmpfs），Windows MUST 固定为当前用户主目录下的 `.rust-knowledge-server/`（本地持久化块存储）。Qdrant 数据与索引、发布目录表、导入暂存、审计、锁和其他服务文件 MUST 仅写入该根，MUST NOT 写入工作目录、其他应用目录、NFS 或额外缓存目录。

#### Scenario: 普通用户直接启动
- **WHEN** 未提权的用户直接运行程序，该平台固定路径的父目录可用，且目标目录不存在
- **THEN** 服务建立固定数据根并使用它；CentOS 7 数据根仅允许启动用户访问；不修改操作者保管的原始 Markdown，也不读取或迁移其他路径上的旧数据

#### Scenario: 固定数据根不可用或被重定向
- **WHEN** 固定根不可读写、存在符号链接重定向、所在文件系统不受支持，或 CentOS 7 固定根已存在但不归启动用户独占
- **THEN** 服务报告路径或存储错误，不启动 HTTP 服务，不访问被重定向的目录、不修改现有数据、不回退其他路径

### Requirement: 服务托管数据库生命周期

服务 MUST 按数据操作的需要自行初始化、打开及关闭嵌入式数据库；数据根 MUST 由单个服务进程独占。CentOS 7 的托管目录 MUST 与数据根位于同一 tmpfs 挂载；Windows MUST 保留本地持久化存储校验。

#### Scenario: 首次并发使用同一知识库
- **WHEN** 服务已启动并收到同一知识库的一组并发数据操作
- **THEN** 服务只拥有一个该索引版本的有效数据库实例；首次操作自动按需打开或创建，用户不用执行数据库命令

#### Scenario: 数据根保留时重启进程
- **WHEN** 服务进程退出或中断后用同一数据根重启，原有发布数据仍在
- **THEN** 服务重新打开原有数据并返回已发布证据，不要求重新导入，不静默重置索引

#### Scenario: CentOS 7 机器重启后重新导入
- **WHEN** CentOS 7 机器重启导致 tmpfs 内容丢失，服务重新启动
- **THEN** 服务以空库启动，不恢复旧索引、库目录或审计，不从其他路径寻找数据；操作者可用独立保管的 Markdown 重新建库并导入

#### Scenario: 数据根已被占用或索引打开失败
- **WHEN** 数据根已被另一个实例使用，或已有发布数据损坏
- **THEN** 前者拒绝启动；后者对受影响的操作返回存储错误，不伪装成零命中，不清空已有数据

#### Scenario: 已发布索引缺失数据
- **WHEN** 已发布索引配置仍在，但其必要数据文件缺失，随后查询该索引
- **THEN** Web 和 MCP 均返回存储错误，不重建为空索引，也不返回成功零命中

#### Scenario: tmpfs 容量不足时不替换旧版
- **WHEN** CentOS 7 重导时 tmpfs 空间不足，无法提交完整新版本
- **THEN** 导入失败并报告存储错误，已有发布版本保留，不向其他位置写入

### Requirement: 上传 Markdown 并发布完整版本

服务 MUST 仅以一批上传的 UTF-8 `.md` 文件（扩展名不区分大小写）及其相对路径建立整库版本。上传路径 MUST 使用以 `/` 分段的库内相对路径；拒绝绝对路径、盘符、反斜杠、控制字符、空路径段、`.`、`..` 和批内重复路径，不访问路径指向的本机文件。导入 MUST 保留原始证据、相对路径、一基闭区间行号和原文档字节的 SHA-256；只发布完整的关键词索引，可选向量缺失不阻止发布。

#### Scenario: 导入保留技术证据与定位
- **WHEN** 上传包含目录层级、代码围栏和长段落的 Markdown 文档
- **THEN** Web 和 MCP 均可查到实际导入的正文、库名、相对路径与行号，Web 保留原文档 SHA-256，MCP 通过命中引用补读；原始 Markdown 及 CRLF 换行保持不变，围栏内的伪标题不会拆节，搜索和补读不访问上传者的文件系统

#### Scenario: 无效文件或路径不替换既有版本
- **WHEN** 上传批次包含非 `.md` 文件、非 UTF-8 Markdown、非法相对路径或重复路径
- **THEN** 拒绝整批导入并指出问题，不发布部分批次，既有版本不变

#### Scenario: 重导期间失败或中断
- **WHEN** 正在为已有知识库重导，而导入在发布前失败或进程中断
- **THEN** Web 和 MCP 不看到半成品；数据根保留时，已有发布版本在进程重启后仍可查询，首次导入失败时不得产生可搜索的版本

#### Scenario: 重导以完整上传批替换旧语料
- **WHEN** 已发布版本包含 `a.md` 和 `b.md`，提交并成功发布仅包含 `a.md` 的重导
- **THEN** 发布前仍可查询旧版本；发布后新查询只在本批资料中检索，未上传的 `b.md` 不再可查

#### Scenario: 查找与版本切换并发
- **WHEN** 同一次搜索跨越新版本发布时点
- **THEN** 该搜索的正文与来源只来自它开始检索时选定的版本，不拼接两代证据；新搜索可见新发布版本

#### Scenario: 删除完成后旧导入不能发布
- **WHEN** 某库的导入还未发布，该库已被成功删除，之后旧任务尝试发布，不论该名称是否已重新建库
- **THEN** 旧导入不能恢复已删除的库、发布旧证据或改变同名新库，导入状态不得报告成功

### Requirement: 共享检索及准确来源

等效的 Web 和 MCP 搜索 MUST 使用同一检索逻辑。基础关键词搜索不依赖模型；可用的已配置 Embedding 能补充语义召回，但故障 MUST 保留关键词结果，不掩盖基础索引错误。每条证据 MUST 可定位到已导入正文及其来源。Web 保持原有证据与诊断字段；MCP 在共享排序之后按自身契约去重、限制条数并裁剪原文。

#### Scenario: 关键词和完整技术名称
- **WHEN** 查询 `C++` 或 `std::vector`，已导入资料包含完整写法及近似写法
- **THEN** 完整技术名称优先于相关证据；名称匹配忽略大小写但保留内部标点，按原始上下文判断边界，不将 `C++17` 中的子串、切片边界、散落词元或仅语义相似标成完整命中；没有完整命中时明确区分，来自不同来源的相同正文仍各自可定位

#### Scenario: 普通查询不隐式解释语法
- **WHEN** 搜索词或自然语言查询包含引号、通配符、布尔词或正则符号
- **THEN** 仍作为普通检索文本处理，不开启短语、通配符、布尔或正则查询语法；技术名称仍保留必要的标点

#### Scenario: 范围在召回之前生效
- **WHEN** 调用方指定知识库或库内相对路径范围，且范围外存在排名更高的候选
- **THEN** 仅在有效范围内召回和排序，范围外候选不占预算，范围外的语料统计也不改变范围内的关键词排序

#### Scenario: 已建库但没有发布版本
- **WHEN** 指定存在但尚未发布的库，或未指定库且服务当前没有任何已发布版本
- **THEN** 返回「无已发布索引」，不创建索引，不把它当成正常零命中或存储损坏；未指定库且已有已发布版本时仅搜索已发布库

#### Scenario: Embedding 缺失或不可用
- **WHEN** 关键词索引可用，但未配置 Embedding、查询向量不可用，或所选范围的部分或全部库版本没有完整兼容的向量
- **THEN** 每个库的关键词证据仍可用；只在当前模型、维度、编码约定及语料版本均匹配的库版本内做语义召回，无可用语义分支时回退关键词；Web 在两种情况下都如实标明实际检索方式

#### Scenario: 正常零命中与故障可辨识
- **WHEN** 已发布语料的有效查询没有命中，或查询因索引不可用而无法执行
- **THEN** 前者返回范围内零命中，后者返回明确错误；两者不得互相替代

### Requirement: 可选 Rerank 精排与基础排名回退

服务 MUST 支持独立配置的 Rerank API；除 CentOS 7 自动配置生效时外，未显式配置默认关闭。精排 MUST 只在普通搜索的全文或混合基础排名之后运行，只调整本次有效范围内的有限候选顺序，不改变结果集合、原文、来源或命中类别。Web MUST 如实标明本次是否实际采用精排；Web 与 MCP 均不提供逐次查询的精排控制参数，MCP 不返回精排状态。

#### Scenario: 有效精排只调整同类候选顺序
- **WHEN** 已配置的 Rerank API 为有限候选返回完整有效的评分，基础排名来自全文或混合检索
- **THEN** 仅在同一命中类别内按评分调整该窗口，同分保留原相对顺序，窗口外证据不变，完整名称始终优先于相关证据

#### Scenario: 精排关闭、失败或响应无效
- **WHEN** Rerank 未配置、请求失败，或返回不匹配的模型、缺失／重复／越界的候选索引或非有限分数
- **THEN** 共享检索保留完整的基础结果和原顺序，Web 标明未采用精排；未配置时不发请求，不探测其他地址或下载模型

#### Scenario: 没有候选时不请求精排
- **WHEN** 没有已发布索引、基础搜索失败或基础结果为空
- **THEN** 不调用 Rerank API，保留原有查询结果或错误

### Requirement: 限定部署访问和资料共享范围

由于工号不验证身份、Web 活动记录无需登记且 MCP 不要求登录，部署 MUST 将 Web 和 MCP 限定在运维明确批准的网络访问范围内，并且只导入获准向该范围共享的资料。所有能访问 Web 的访客均可见自报工号和知识库操作记录，部署 MUST 确认该范围获准共享这些记录；不另设应用内查看权限。

自动启用模型的部署还 MUST 确认可将检索查询和导入或候选文档片段发送至配置的网关；Web 和 MCP 的共享许可不替代该授权。

#### Scenario: 默认地址和远程访问
- **WHEN** 服务以默认设置启动，或明确通过 `--listen` 绑定回环地址
- **THEN** 默认绑定 `0.0.0.0:9333`，本机和网络可达的其他机器均可访问 Web 与 MCP；显式绑定回环地址时限本机访问。两种情况均按连接的服务端 IP、端口校验 Host，回环连接也接受同端口的 `localhost`。

#### Scenario: 从批准范围内外分别访问
- **WHEN** 从批准范围内及范围外发起连接
- **THEN** 范围内的 Web 和原生 MCP 客户端能访问相应入口；范围外不能访问任一入口；验收语料、自报工号和活动记录有批准的共享范围记录
