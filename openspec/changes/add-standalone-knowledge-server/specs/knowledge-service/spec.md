# Spec Delta

## Purpose

规定独立知识库服务的交付与持久化合同：在公司内网通过 Markdown 上传建立共享知识库，并让浏览器和 MCP 查询同一批已发布的原始证据。

## ADDED Requirements

### Requirement: Windows 和 CentOS 7 单文件运行

服务 MUST 分别为 Windows x64 与 CentOS 7 x64 交付一个可执行文件，内含 Web 资源和进程内数据库能力；不承诺其他平台。服务 MUST 独立运行，MUST NOT 依赖任何客户端运行时、独立 Qdrant 进程、附带数据库程序、容器、外部前端文件或启动时联网下载。

#### Scenario: 干净环境离线启动
- **WHEN** 用户在受支持的 Windows x64 或 CentOS 7 x64 环境仅取得对应可执行文件，并提供可写的持久化数据目录
- **THEN** 该文件独立启动 HTTP 服务，提供浏览器与 MCP 入口，无需另行安装或启动数据库，也不对外监听数据库接口
- **AND** 文档索引与操作记录不写入可执行文件，更换可执行文件或用同一数据目录重启后仍可访问已持久化的数据

### Requirement: 统一的知识库文件根

服务 MUST 使用 `OMP_CONFIG_ROOT` 统一定位所有自身管理的文件。有效绝对路径（含 `~` 展开后得到的绝对路径）下使用 `rust-knowledge-server/` 子目录；未设置或相对路径时使用用户主目录下的 `.rust-knowledge-server/`。服务 MUST NOT 读写其他应用自身的文件或另设缓存根。

#### Scenario: 显式根下集中存放
- **WHEN** 服务以有效 `OMP_CONFIG_ROOT` 启动、导入文档并完成 Web 操作
- **THEN** 配置、Qdrant 数据和索引、导入暂存、操作记录、服务日志、锁和其他服务管理的文件均在 `<OMP_CONFIG_ROOT>/rust-knowledge-server/` 下；可执行文件和用户的原始文档不受影响

#### Scenario: 未设置或使用相对路径
- **WHEN** 未设置 `OMP_CONFIG_ROOT`，或展开后仍为相对路径
- **THEN** 服务使用当前用户主目录下的 `.rust-knowledge-server/`，不以工作目录为基准写入

#### Scenario: 显式根不可用
- **WHEN** 指定的绝对根不可用、不具备写权限或不满足持久化存储要求
- **THEN** 服务明确报告路径错误，不退回默认目录、临时目录或其他路径

### Requirement: 服务托管数据库生命周期

服务 MUST 按数据操作的需要自行初始化、打开及关闭嵌入式数据库。实际数据目录 MUST 使用持久化块存储；解析后的显式根或默认根位于 NFS、其他网络文件系统或易失存储时 MUST 拒绝启动，即使目录可写，也不得另选目录继续运行。

#### Scenario: 首次并发使用同一知识库
- **WHEN** 服务已启动并收到同一知识库的一组并发数据操作
- **THEN** 服务只拥有一个该索引版本的有效数据库实例；首次操作自动按需打开或创建，用户不用执行数据库命令

#### Scenario: 重启后重新使用已发布知识库
- **WHEN** 服务停止后以同一持久化目录重新启动并查询已发布知识库
- **THEN** 服务重新打开原有数据并返回已发布证据，不要求重新导入，不静默重置索引

#### Scenario: 数据目录不可用或索引打开失败
- **WHEN** 持久化目录不可读写、已有数据损坏或目录已被另一个实例使用
- **THEN** 对受影响的操作返回可辨识错误，不伪装成零命中，不清空数据或落到临时数据库

#### Scenario: 已发布索引缺失数据
- **WHEN** 已发布索引配置仍在，但其必要数据文件缺失，随后查询该索引
- **THEN** Web 和 MCP 均返回存储错误，不重建为空索引，也不返回成功零命中

#### Scenario: 可写网络盘不可作为索引盘
- **WHEN** `OMP_CONFIG_ROOT` 解析后的服务目录位于可写的 NFS 或其他网络文件系统
- **THEN** 启动明确报告存储不受支持，不创建索引，不回退其他位置

### Requirement: 上传 Markdown 并发布完整版本

服务 MUST 仅以一批上传的 UTF-8 `.md` 文件（扩展名不区分大小写）及其相对路径建立整库版本。上传路径 MUST 使用以 `/` 分段的库内相对路径；拒绝绝对路径、盘符、反斜杠、控制字符、空路径段、`.`、`..` 和批内重复路径，不访问路径指向的本机文件。导入 MUST 保留原始证据、相对路径、一基闭区间行号和原文档字节的 SHA-256；只发布完整的关键词索引，可选向量缺失不阻止发布。

#### Scenario: 导入保留技术证据与定位
- **WHEN** 上传包含目录层级、代码围栏和长段落的 Markdown 文档
- **THEN** 可查到实际导入的正文、库名、相对路径、行号范围和原文档 SHA-256；原始 Markdown 及 CRLF 换行保持不变，围栏内的伪标题不会拆节，查询不读取原始文件系统

#### Scenario: 无效文件或路径不替换既有版本
- **WHEN** 上传批次包含非 `.md` 文件、非 UTF-8 Markdown、非法相对路径或重复路径
- **THEN** 拒绝整批导入并指出问题，不发布部分批次，既有版本不变

#### Scenario: 重导期间失败或中断
- **WHEN** 正在为已有知识库重导，而导入在发布前失败或进程中断
- **THEN** Web 和 MCP 不看到半成品，已有发布版本在重启后仍可查询；首次导入失败时不得产生可搜索的版本

#### Scenario: 重导以完整上传批替换旧语料
- **WHEN** 已发布版本包含 `a.md` 和 `b.md`，提交并成功发布仅包含 `a.md` 的重导
- **THEN** 发布前仍可查询旧版本；发布后新查询只在本批资料中检索，未上传的 `b.md` 不再可查

#### Scenario: 查找与版本切换并发
- **WHEN** 同一次搜索跨越新版本发布时点
- **THEN** 该搜索的正文与来源只来自它开始检索时选定的版本，不拼接两代证据；新搜索可见新发布版本

#### Scenario: 删除完成后旧导入不能发布
- **WHEN** 某库的导入还未发布，该库已被成功删除，之后旧任务尝试发布，不论该名称是否已重新建库
- **THEN** 旧导入不能恢复已删除的库、发布旧证据或改变同名新库，导入状态不得报告成功

### Requirement: 共享检索及准确来源

等效的 Web 和 MCP 搜索 MUST 使用同一检索逻辑。基础关键词搜索不依赖模型；可用的已配置 Embedding 能补充语义召回，但故障 MUST 保留关键词结果，不掩盖基础索引错误。每条证据 MUST 可定位到已导入正文及其来源。

#### Scenario: 关键词和完整技术名称
- **WHEN** 查询 `C++` 或 `std::vector`，已导入资料包含完整写法及近似写法
- **THEN** 完整技术名称优先于相关证据；名称匹配忽略大小写但保留内部标点，按原始上下文判断边界，不将 `C++17` 中的子串、切片边界、散落词元或仅语义相似标成完整命中；没有完整命中时明确区分，来自不同来源的相同正文仍各自可定位

#### Scenario: 普通查询不隐式解释语法
- **WHEN** 搜索词或自然语言查询包含引号、通配符、布尔词或正则符号
- **THEN** 仍作为普通检索文本处理，不开启短语、通配符、布尔或正则查询语法；技术名称仍保留必要的标点

#### Scenario: 范围在召回之前生效
- **WHEN** 调用方指定知识库或库内相对路径范围，且范围外存在排名更高的候选
- **THEN** 仅在有效范围内召回和排序，范围外候选不占预算，范围外的语料统计也不改变范围内的关键词排序

#### Scenario: 已建库但没有发布版本
- **WHEN** 指定存在但尚未发布的库，或未指定库且服务当前没有任何已发布版本
- **THEN** 返回「无已发布索引」，不创建索引，不把它当成正常零命中或存储损坏；未指定库且已有已发布版本时仅搜索已发布库

#### Scenario: Embedding 缺失或不可用
- **WHEN** 关键词索引可用，但未配置 Embedding、查询向量不可用，或所选范围的部分或全部库版本没有完整兼容的向量
- **THEN** 每个库的关键词证据仍可用；只在当前模型、维度、编码约定及语料版本均匹配的库版本内做语义召回，无可用语义分支时回退关键词，并在两种情况下都如实标明实际检索方式

#### Scenario: 正常零命中与故障可辨识
- **WHEN** 已发布语料的有效查询没有命中，或查询因索引不可用而无法执行
- **THEN** 前者返回范围内零命中，后者返回明确错误；两者不得互相替代

### Requirement: 可选 Rerank 精排与基础排名回退

服务 MUST 支持独立配置的 Rerank API，默认关闭。精排 MUST 只在普通搜索的全文或混合基础排名之后运行，只调整本次有效范围内的有限候选顺序，不改变结果集合、原文、来源或命中类别。Web 和 MCP MUST 如实标明本次是否实际采用精排，不提供逐次查询的精排控制参数。

#### Scenario: 有效精排只调整同类候选顺序
- **WHEN** 已配置的 Rerank API 为有限候选返回完整有效的评分，基础排名来自全文或混合检索
- **THEN** 仅在同一命中类别内按评分调整该窗口，同分保留原相对顺序，窗口外证据不变，完整名称始终优先于相关证据

#### Scenario: 精排关闭、失败或响应无效
- **WHEN** Rerank 未配置、请求失败，或返回不匹配的模型、缺失／重复／越界的候选索引或非有限分数
- **THEN** 保留完整的基础结果和原顺序，标明未采用精排；未配置时不发请求，不探测其他地址或下载模型

#### Scenario: 没有候选时不请求精排
- **WHEN** 没有已发布索引、基础搜索失败或基础结果为空
- **THEN** 不调用 Rerank API，保留原有查询结果或错误

### Requirement: 限定部署访问和资料共享范围

由于工号不验证身份且 MCP 不要求登录，部署 MUST 将 Web 和 MCP 限定在运维明确批准的内网访问范围内，并且只导入获准向该范围共享的资料；这不引入应用内身份或权限模型。

#### Scenario: 从批准范围内外分别访问
- **WHEN** 从批准范围内及范围外发起连接
- **THEN** 范围内的 Web 和原生 MCP 客户端能访问相应入口；范围外不能访问任一入口；验收语料有批准的共享范围记录
