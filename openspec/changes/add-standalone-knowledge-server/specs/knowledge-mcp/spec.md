# Spec Delta

## Purpose

提供标准 Streamable HTTP MCP 接口，让兼容客户端能发现并调用同一个只读知识库工具，无需专用集成或浏览器会话。

## ADDED Requirements

### Requirement: 标准 Streamable HTTP 接入

服务 MUST 在同一个 `/mcp` 地址提供标准 Streamable HTTP MCP，并支持客户端完成协议初始化、工具发现和工具调用。客户端 MUST NOT 依赖专用代理、自定义传输、登记工号、浏览器会话或登录凭据。

#### Scenario: 两个独立的原生客户端使用同一地址
- **WHEN** 两个独立的 MCP 客户端各自使用原生 Streamable HTTP 配置连接同一服务地址
- **THEN** 两者能完成协议握手，发现并调用 `knowledge_search`，取得本次检索的原文证据和来源

#### Scenario: 请求 Host 与来源校验
- **WHEN** 原生客户端连接服务，以实际服务端 IP 和端口作为 Host 且不发送 `Origin`，或请求携带不匹配的 Host 或不允许的 `Origin`
- **THEN** 前者可完成标准 MCP 初始化；后者返回 HTTP 403、不执行工具调用

#### Scenario: MCP 不提供管理操作
- **WHEN** 客户端发现工具或试图经 MCP 创建、导入或删除知识库
- **THEN** 不会发现这些写工具，调用也不能造成写入；MCP 请求不会被归到任何已登记的浏览器工号

### Requirement: 查询输入和返回证据

`knowledge_search` MUST 接受非空的查询词或自然语言文本 `query`，以及可选的库名 `library` 和库内相对路径范围 `path`。`path` 采用与导入相同的路径格式，按完整路径匹配单文件或按 `/` 分段匹配目录子树；未指定 `library` 时路径范围应用于所有已发布库。结果 MUST 提供真实原文、库名、相对路径、一基闭区间行号、原文档 SHA-256、完整名称或相关命中类别、实际检索方式及是否采用精排，不把相关候选或精排分数表述为已证实事实。

#### Scenario: 与浏览器查询一致
- **WHEN** Web 和 MCP 对相同的发布版本集合提交等效查询，且实际检索与精排条件相同（包括有效召回和评分输入）
- **THEN** 两者返回相同的范围、证据与顺序，来源可定位导入时的原文

#### Scenario: 单次请求独立降级
- **WHEN** 同一已发布版本的等效 Web 与 MCP 查询中，只有一个请求无法使用 Embedding 或 Rerank
- **THEN** Embedding 不可用的一方回退关键词，Rerank 不可用的一方保留基础排名，两端各自标明实际检索和精排状态；不要求不同条件下给出相同排序

#### Scenario: 无效输入、无已发布索引、零命中和故障
- **WHEN** 客户端传入空白查询、指定不存在的库或非法路径，或有效查询遇到无已发布索引、范围内没有匹配、底层索引不可用
- **THEN** 分别返回参数错误、无已发布索引、正常零命中或存储错误；合法但未命中文件的路径范围在已有发布版本时属于零命中，不把无效调用及故障包装为成功空结果
