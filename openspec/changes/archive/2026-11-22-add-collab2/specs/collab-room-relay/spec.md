# Spec Delta

## Purpose

让内网同事在 Windows 和 CentOS 7 上通过同一个房间号加入并操作主持人的 OMP 会话。知识库复用现有服务入口完成房间发现和消息中继，保留原生 Collab 的会话协作语义。

## ADDED Requirements

### Requirement: 房间号登记不覆盖现有房间

服务 MUST 在接纳主持 WebSocket 后确认连接可登记，并仅为仍存续的主持连接登记房间号。同号登记必须原子拒绝，不得覆盖；登记只在内存中有效。

#### Scenario: 用指定号码开房
- **WHEN** 主持人在 OMP TUI 输入 `/collab2 <房间号>`，本实例未在主持或参与其他协作，且该房间号未占用
- **THEN** 该号码可查到主持人当前会话的可写加入信息，客户端在登记成功后才报告开房成功。

#### Scenario: 同号竞争或登记失败
- **WHEN** 两个主持实例并发登记同一号码，或实例尝试登记已经占用的号码
- **THEN** 最多一个登记成功；冲突一方收到明确的占用错误，不覆盖原登记，只撤销自己的未发布原生房间。原主持人及来宾不受影响。

#### Scenario: 主持连接不存在
- **WHEN** 登记对应的原生主持连接尚未建立或已经关闭
- **THEN** 服务拒绝登记，不发布无法加入的房间号。

#### Scenario: 本实例已有协作
- **WHEN** 本实例正在主持或已加入原生协作，且用户尝试 `/collab2 <房间号>`
- **THEN** 客户端拒绝开房，不复用、不替换、不关闭已有协作。

### Requirement: 通过房间号直接可写加入

服务 MUST 向知道有效房间号的客户端返回原生可写加入所需的信息。配套 OMP 客户端 MUST 复用原生可写加入流程，不要求工号、身份配置、认证或加入确认。

#### Scenario: 两位同事加入同一会话
- **WHEN** B、C 在各自 OMP TUI 输入 `/collab2 join <房间号>` 并加入 A 的有效房间
- **THEN** 两位来宾都能看见 A 的会话和实时更新，各自能向 A 端 Agent 发送消息；可写权限与原生 Collab 可写加入一致，不要求 A 逐人确认。

#### Scenario: 查询不存在或已关闭的号码
- **WHEN** 客户端查询不存在或已撤销的房间号
- **THEN** 服务明确返回房间不可用，不提供旧房间或其他房间的加入信息。

### Requirement: 房间只在其主持连接存续时可加入

房间 MUST 绑定首次主持连接。主持连接关闭或失联超时，服务 MUST 撤销房间号、拒绝对旧房的加入并关闭来宾连接。新的开房操作使用新的原生房间 ID，不自动恢复旧房间号。

#### Scenario: 主动关房、切换会话或主持退出
- **WHEN** A 用 `/collab2 stop` 关闭自己的房间、切换到其他会话或退出，导致原生主持连接关闭
- **THEN** 旧房间号不再可查询或加入，已加入的来宾结束旧房协作；切换会话不会自动把旧号码绑定到新会话。

#### Scenario: 主持失联后手动重开
- **WHEN** 主持连接意外断开或失联超时，后来主持人手动用同一号码开房
- **THEN** 旧房结束，房号可以登记到新房；已取得的旧加入信息不能加入新房。

#### Scenario: 服务进程停止或重启
- **WHEN** 知识库服务停止或重启
- **THEN** 现有协作连接结束，旧号码不会从持久数据中恢复。

### Requirement: 兼容原生协作中继协议与部署约束

知识库 MUST 在现有 HTTP 监听上提供 Web、MCP、协作登记和查询，并通过同端口 `/r/{roomId}` 提供原生 WS 中继；本机与跨机均不依赖 HTTPS、WSS 或 TLS 代理。服务不得解密或替换原生会话帧，不得记录房间号、加入链接、密钥、写令牌或会话内容。Web 和 MCP 的既有行为及访问校验不变。

#### Scenario: Windows 本机连接
- **WHEN** 一个知识库实例和多个配套 OMP TUI 实例在 Windows 本机运行，且未设置 `OMP_COLLAB2_IP`
- **THEN** OMP MUST 默认通过 `http://127.0.0.1:9333` 登记和查询，通过 `ws://127.0.0.1:9333` 转发原生加密会话帧。

#### Scenario: 两个平台互换主持端
- **WHEN** Windows 与 CentOS 7 用户各自将 `OMP_COLLAB2_IP` 设为同一个知识库的内网 IP，并互换主持端
- **THEN** OMP MUST 连接指定 IP 的 `9333` 端口，使用 HTTP 登记和查询、使用 WS 转发原生加密会话帧；两个方向都能实时协作和发送消息。登记和查询链路是明文，房间号授予可写权限，跨机入口 MUST 仅在可信隔离内网开放。

#### Scenario: 既有入口回归
- **WHEN** 发布启用协作的知识库及配套 OMP
- **THEN** 原有 `/collab` 和 `/join` 仍按原生链接工作，不允许非回环明文 WS；Web 与 MCP 继续通过既有 HTTP 入口和访问校验正常使用。
