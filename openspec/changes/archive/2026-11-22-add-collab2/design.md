# Design

## Context

`src/main.rs` 在一个 Axum HTTP 监听上挂载静态页面、Web 和 MCP，通过 `require_http_access` 核对请求 Host 和连接端点，并用 `CancellationToken` 与 `TaskTracker` 管理停机。当前监听不终止 TLS，锁定的 Axum 依赖尚未启用 `ws`。

配套 OMP 已有 `CollabController`、`CollabGuestLink` 和 `packages/collab-web/scripts/local-relay.ts`。原生主持端生成随机 `roomId`、32 字节房间密钥和 16 字节写令牌；完整链接同时包含后二者，`viewLink` 不含写令牌。Rust 中继按参考中继的传输语义工作，不需要实现端点的会话协议或加密。

## Goals / Non-Goals

**Goals:**

- 让房间号的发布和撤销与一个确切的原生主持连接绑定，而不是绑定到进程可重用的槽位或某个当前会话。
- 固定 Rust 与配套 OMP 之间的可写加入契约，两个平台共用同一套服务端和客户端逻辑。

**Non-Goals:**

- 不实现独立群聊、旁观模式、浏览器协作页、身份目录、会话持久化或第二套加密。
- 不改变 Web/MCP 的 Host 或来源校验，不改原有 `/collab`、`/join`，不在本仓库交付 OMP 客户端。

## Decisions

1. **同一个 Axum 监听。** 启用 Axum `ws`，把新路由与 Web/MCP 合并，沿用现有 Host 校验。WS 升级和连接用现有取消与任务跟踪，返回升级响应前纳入跟踪；升级失败、连接关闭和停机均清理房间。不另建端口、进程或存储。
2. **登记和查询只交换房间数据。** `POST /api/collab2/rooms` 接收 `{roomNumber, roomId, secret}`，成功返回 `201`；`POST /api/collab2/lookup` 接收 `{roomNumber}`，成功返回 `200` 和 `{roomId, secret}`。`secret` 为原生 32 字节房间密钥与 16 字节写令牌拼接后的 Base64URL 值。房间号区分大小写、保留前导零，接受 1–64 个 ASCII 字母、数字、连字符或下划线，保留 `join`、`stop`。无效输入返回 `400`，房间或主持连接不存在返回 `404`，重号返回 `409`。号码和秘密不进入 URL 或错误正文，协作 HTTP 响应不缓存。
3. **首次主持连接就是房间寿命。** 每次开房生成新的随机 `roomId`。中继在确认主持 WebSocket 已接纳并装入房间后，向该连接发文本控制消息 `{"t":"host-ready"}`；OMP 收到后才登记，不把 HTTP `101` 当成接纳。用同一内存状态维护主持连接和房间号，原子完成存续检查、冲突判定与写入。主持关闭或超时后，删除该连接及其登记，再关闭来宾。复用 WS ping/pong 做简单的有界失联清理，不为旧房 ID 自动重连或补登。不增加连接代次、额外令牌、等待登记队列或远程删除接口。
4. **复用原生转发协议。** 接受 `/r/{roomId}?role=host|guest`；参考原生中继处理主持重复（`4009`）、房间不存在（`4004`）、按 4 字节 peer ID 转发二进制帧以及 `peer-joined`、`peer-left`、`room-closed` 控制消息。关房以 `4001` 关闭来宾；OMP 仅在 `/collab2` 路径将断线作为终态。用有界连接发送队列和足以承载原生快照的帧上限，不解密业务帧。
5. **HTTP/WS 直连现有知识库监听，不引入 TLS。** OMP 默认使用 `127.0.0.1:9333`，`OMP_COLLAB2_IP` 只替换 IP；客户端直连，不走代理。仅 `/collab2` 允许配置 IP 的远程明文 WS。知识库只供本机使用时显式绑定 `127.0.0.1:9333`；跨机时同一 `9333` 端口仅对可信隔离内网可达。Web、MCP 的接口与 Host/Origin 校验不变。

## Risks / Trade-offs

- 房间号授予控制权限，猜中号码的网络可达者也能向主持 Agent 发指令。→ 不提供房间枚举；将入口限制在获准协作的网络范围内，使用难猜的房间号，不加应用鉴权。
- 房间密钥和写令牌通过 HTTP 明文传输，能监听链路的人可取得会话控制权，并可能解密会话帧；服务本身也持有密钥。→ 仅在可信隔离内网开放跨机协作，不把原生帧加密视为链路加密；不记录房间号、链接、密钥、写令牌或正文，也不将其写入审计或磁盘。
- 查询与关房并发时，已返回的加入信息可能在来宾握手前失效。→ 以实际主持连接和原生握手为准；不回退到新房或同名房间，不把查询成功当作已经加入。

## Migration Plan

无需迁移数据。先验证知识库原有 HTTP Web/MCP，再部署配套 OMP 并验证默认回环地址；跨机仅在可信隔离内网让两端设置同一 `OMP_COLLAB2_IP` 后验收，不部署 TLS。回滚时停止协作使用并退回上一版知识库和 OMP；内存房间自然失效，知识库数据布局不变。
